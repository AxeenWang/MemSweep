> 標示「〔Claude 決定〕」的條文，是討論中由 Claude 提出、使用者沒有反對的預設值，之後仍可推翻。其餘條文是使用者表明的需求。

## 1. 背景

### 1.1 使用者與電腦

- 唯一的使用者是作者本人。電腦是 Windows 11 筆電，實體 RAM 32 GB。
- 分頁檔原本固定 8 GB，commit 上限約 39.4 GB。使用者計畫改為固定 32 GB（初始 = 最大 = 32768 MB），上限約 63 GB。

### 1.2 問題

使用者撰寫單機遊戲的修改器，會在遊戲執行中請 Claude Code 分析遊戲，同時還開著多個 AI 與開發工具。commit 用盡時，即使實體 RAM 還有空，新程式也要不到記憶體：遊戲開不起來，Claude 底下的 node 行程出現 ENOMEM 而失敗。

2026-10-26 未開遊戲時的實測（唯讀查詢）：

| 項目 | 數值 |
| --- | --- |
| commit 已用 / 上限 | 31.4 / 39.4 GB（剩 8.0 GB） |
| 實體 RAM 已用 / 總量 | 20.5 / 31.4 GB |
| Claude 桌面版（36 個行程，含 MCP） | 3.2 GB |
| ChatGPT / VS Code / Codex | 2.2 / 1.5 / 0.5 GB |
| 其他 node 行程（多為 MCP，約 30 個） | 約 1.4 GB |
| 所有行程的私有 commit 總和 | 24.5 GB |
| 不屬於任何行程的 commit | 約 6.9 GB |

### 1.3 為什麼不做「記憶體清理器」

市面上的清理器修剪工作集、清除待命清單，只讓「使用中」的數字變好看，不會減少 commit，解決不了這個問題。能減少 commit 的只有結束佔用的程式或加大分頁檔，這兩件事由使用者自己決定。MemSweep 的角色是讓使用者看清楚、記下來，並讓 Claude 在吃記憶體的工作開始前先檢查。

## 2. 名詞

| 名詞 | 定義 |
| --- | --- |
| commit 已用 | Windows 已承諾給所有程式與系統的記憶體總量，即工作管理員「記憶體」頁「已認可」的前一個數字 |
| commit 上限 | 實體 RAM 加上分頁檔大小，即「已認可」的後一個數字 |
| commit 使用率 | commit 已用 ÷ commit 上限 |
| 剩餘 commit | commit 上限 − commit 已用 |
| 行程 commit | 單一行程的私有 commit，即工作管理員「詳細資料」頁的「認可大小」 |
| 應用程式 | 一個最上層行程加上歸屬它的子孫行程，合成一列顯示，規則見第 8 章 |
| 系統（不屬於任何程式） | commit 已用 − 所有行程 commit 的總和 |
| 開機以來尖峰 | Windows 記錄的本次開機以來 commit 已用的最高值 |

## 3. 目標

- G-1 隨時一眼看到 commit 使用率。
- G-2 看出 commit 被哪些應用程式佔用。
- G-3 記錄 commit 尖峰，作為調整分頁檔大小的依據。
- G-4 Claude 在進行吃記憶體的分析前，能用命令列檢查剩餘 commit，不足時停下來問使用者。

## 4. 非目標（第一版不做）

- N-1 清理：修剪工作集、清除待命或已修改分頁清單、清空檔案快取。
- N-2 結束、暫停或調整任何程式。
- N-3 需要系統管理員權限的功能。
- N-4 通知、彈窗與聲音。提醒只靠系統匣圖示變色。
- N-5 任何網路功能：不上傳、不檢查更新、不回報使用資料。
- N-6 安裝程式。
- N-7 細分「系統（不屬於任何程式）」的組成。
- N-8 修改分頁檔或其他系統設定。

## 5. 反目標（即使功能都做到也算失敗）

- X-1 MemSweep 本身成為記憶體大戶。常駐時本身的 commit 目標不超過 100 MB。〔Claude 決定〕
- X-2 未經使用者操作就改變系統狀態。
- X-3 顯示的數字和 Windows 工作管理員對不起來，讓使用者無法信任。〔Claude 決定〕

## 6. 執行環境

- E-1 只支援 Windows 11 x64。〔Claude 決定〕
- E-2 需先安裝 .NET 10 Desktop Runtime。〔Claude 決定〕
- E-3 免安裝：兩支 exe 放在使用者有寫入權限的資料夾就能執行。不可放在 `C:\Program Files` 等需要系統管理員權限才能寫入的位置。
- E-4 以一般使用者權限即可使用全部功能。
- E-5 所有系統查詢都是唯讀。

## 7. 功能需求

### 7.1 系統匣圖示（MemSweep.exe）

- F-01 MemSweep 啟動後常駐系統匣，直到使用者手動結束。關閉任何視窗都不會結束 MemSweep。
- F-02 圖示以整數顯示目前的 commit 使用率，例如「80」。
- F-03 數字顏色依門檻變化：低於橘色門檻為綠色；達到橘色門檻但低於紅色門檻為橘色；達到紅色門檻以上為紅色。門檻可在設定調整，預設橘色 70%、紅色 85%。〔預設值：Claude 決定〕
- F-04 每 2 秒更新一次。〔Claude 決定〕
- F-05 滑鼠停在圖示上時顯示提示：commit 已用 / 上限（GB 與百分比）、實體 RAM 已用 / 總量（GB）。
- F-06 左鍵點擊開啟小面板（7.2）。
- F-07 右鍵選單有「開啟小面板」、「完整清單…」、「設定…」、「結束 MemSweep」。〔Claude 決定〕

### 7.2 小面板

- F-10 從螢幕右下角彈出，點面板以外的地方就收起。
- F-11 內容：
  - commit 量表：已用 / 上限（GB）與使用率，顏色規則同 F-03。
  - 實體 RAM 量表：已用 / 總量（GB）與使用率。
  - 開機以來尖峰：數值與發生時間，規則見 F-31。
  - commit 前五名的應用程式：名稱、行程數、commit（GB）、相對長條。
  - 「系統（不屬於任何程式）」一列，固定顯示在前五名之後。
- F-12 按鈕：
  - 「完整清單…」：開啟完整視窗（7.3）。
  - 「複製報告」：把與 `memsweep-cli status`（F-40）相同的純文字摘要複製到剪貼簿。〔Claude 決定〕
  - 「結束 MemSweep」。

### 7.3 完整視窗

- F-20 一般視窗，可調整大小。關閉視窗只會收起，MemSweep 繼續常駐。
- F-21 有三個分頁：總覽、程式、尖峰紀錄。
- F-22 總覽：F-11 的全部資訊，另加目前的分頁檔大小。〔Claude 決定〕
- F-23 程式：
  - 所有應用程式依 commit 由大到小排列，欄位為名稱、行程數、commit、實際 RAM（工作集）。
  - 每列可展開，列出組成它的行程，依執行檔名稱合併（例如「claude.exe ×14」）。node 行程再依啟動的套件區分（例如「node：playwright」）。〔Claude 決定〕
  - 最後一列為「系統（不屬於任何程式）」。
- F-24 尖峰紀錄：列出開機尖峰與每日尖峰紀錄（7.4），每筆顯示時間、commit 已用、commit 上限與當時的前五名應用程式。

### 7.4 尖峰紀錄

- F-30 MemSweep 常駐期間每次取樣時，如果 commit 已用創下本次開機或當天的新高，就更新對應的紀錄，並記下那一刻的前五名應用程式（名稱與 commit）。
- F-31 開機尖峰的數值以 Windows 記錄的開機以來尖峰為準。尖峰如果發生在 MemSweep 未執行的期間，該筆的發生時間與前五名標示為「未知」。〔Claude 決定〕
- F-32 每日尖峰以本機時間午夜分日，只計入 MemSweep 執行期間的取樣。
- F-33 每次開機一筆、每天一筆。保留天數可設定，預設 90 天，超過的紀錄自動刪除。〔預設值：Claude 決定〕
- F-34 紀錄存成 CSV，編碼為含 BOM 的 UTF-8，讓 Excel 直接開啟時中文不亂碼。〔Claude 決定〕

### 7.5 命令列（memsweep-cli.exe）

- F-40 `memsweep-cli status`：輸出純文字摘要，包含 commit 已用 / 上限、實體 RAM、開機以來尖峰、前五名應用程式與「系統（不屬於任何程式）」。〔指令形式：Claude 決定〕
- F-41 `memsweep-cli status --json`：以 JSON 輸出相同內容，記憶體數值以 bytes 整數表示。〔Claude 決定〕
- F-42 `memsweep-cli check --need <GB>`：〔Claude 決定〕
  - 剩餘 commit 大於或等於指定的 GB：結束碼 0。
  - 剩餘 commit 不足：結束碼 1，並輸出剩餘 commit 與前五名應用程式。
  - 參數錯誤：結束碼 2。
- F-43 命令列不依賴 MemSweep.exe 是否常駐，直接向系統查詢，全程唯讀，也不讀寫尖峰紀錄檔。

### 7.6 設定

- F-50 可設定的項目：橘色門檻、紅色門檻、開機自動啟動、尖峰紀錄保留天數。
- F-51 開機自動啟動預設關閉。開啟時以目前使用者的身分登記，不需要系統管理員權限。〔Claude 決定〕
- F-52 設定與尖峰紀錄都存放在 exe 所在資料夾下的 `data\` 子資料夾。

### 7.7 其他行為

- F-60 同一時間只允許一個 MemSweep.exe。再次啟動時，叫出既有執行個體的小面板，新的執行個體隨即結束。〔Claude 決定〕
- F-61 介面使用繁體中文，深淺色跟隨 Windows 設定。〔Claude 決定〕

## 8. 應用程式歸組規則〔Claude 決定〕

- R-1 從每個行程往上追父行程，找出它所屬的最上層行程。遇到下列任一情況就停止往上，該行程成為最上層：
  - 父行程是 Windows 殼層或系統行程，例如 explorer.exe、sihost.exe、services.exe、wininit.exe。
  - 父行程已不存在。
  - 該行程是另一個獨立的應用程式，而不是啟動者的一部分。例如從 Steam 啟動的遊戲、在終端機或 IDE 裡執行的 Claude Code 與 Codex CLI、從 IDE 偵錯啟動的修改器、由其他程式開出的瀏覽器。
- R-2 輔助行程一律歸屬啟動它的應用程式，不會因 R-1 第三點而自成一列。輔助行程包含命令列殼層與腳本執行環境（例如 cmd.exe、conhost.exe、pwsh.exe、node.exe、python.exe），以及 msedgewebview2.exe。
- R-3 父行程的建立時間晚於子行程時，視為父行程已不存在，避免行程 ID 被重複使用而誤判。
- R-4 最上層行程加上歸屬它的所有子孫行程，合成一個應用程式。名稱取最上層行程執行檔的檔案描述，取不到時用執行檔名稱。
- R-5 多個最上層行程的執行檔路徑相同時，合併為一列，行程數合計。例如父程式已結束、各自成為最上層的 node 行程，合成一列。
- R-6 執行檔位於 Windows 資料夾（例如 `C:\Windows`）下的最上層行程，全部合併為一列「Windows（系統與服務）」。
- R-7 R-1 第三點「獨立應用程式」的判斷方式（例如比對執行檔的發行者），以及殼層、系統行程與輔助行程的清單，由 Design 決定，實作時可依實測調整。結果必須符合 A-09 的範例。

## 9. 驗收準則

- A-01 commit 已用與上限，和同一時間工作管理員「已認可」顯示的數字相差不超過 0.1 GB。
- A-02 在取樣時間相近時，任一行程的 commit 和工作管理員「詳細資料」頁的「認可大小」相差不超過 5%。
- A-03 MemSweep 常駐 1 小時後，本身的 commit 不超過 100 MB。
- A-04 `check --need` 的結束碼符合 F-42 的三種情況。
- A-05 尖峰紀錄 CSV 以 Excel 直接開啟時，中文正常顯示。
- A-06 以一般使用者權限執行時，所有功能都可用。
- A-07 程式碼中沒有任何改變系統記憶體狀態或提升權限的呼叫，例如 `EmptyWorkingSet`、`SetProcessWorkingSetSize`、`NtSetSystemInformation`、`AdjustTokenPrivileges`。
- A-08 關閉小面板與完整視窗後，MemSweep 仍在系統匣；只有「結束 MemSweep」能結束它。
- A-09 應用程式歸組符合下列範例：
  - 從 Steam 啟動的遊戲自成一列，不併入 Steam。
  - 在終端機或 IDE 裡執行的 Claude Code、Codex CLI 自成一列，不併入終端機或 IDE。
  - Claude 桌面版的工作階段與它啟動的 MCP node 行程，併入 Claude 那一列。
  - WebView2 行程併入使用它的應用程式。
  - 父程式已結束的 node 行程合成一列。

## 10. 技術方向（細節在 Design 定案）

- 使用使用者熟悉的 C# + WPF。
- 以下是 Claude 的建議，在 Design 定案：〔Claude 決定〕
  - .NET 10。
  - 系統匣使用 .NET 內建的 WinForms `NotifyIcon`，不引入第三方套件。
  - Win32 以 `LibraryImport` 呼叫。
  - 拆成 `MemSweep.exe`（WPF 常駐）與 `memsweep-cli.exe`（主控台）兩支 exe，共用一個核心類別庫。
  - framework-dependent 發佈。
